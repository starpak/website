Quick Start快速开始

Prerequisites: Node.js ≥ 18, pnpm ≥ 10. 前置依赖：Node.js ≥ 18，pnpm ≥ 10。

Install dependencies and build all packages: 安装依赖并构建所有包： 

pnpm install
pnpm build

Then run: 然后启动： 

spak serve                    # Start the application
spak serve ./spak.config.yml  # Or specify a config file
spak serve status             # Check runtime status
spak serve --stop             # Stop the running instance
terminal

CLI CommandsCLI 命令

Spak ships a spak binary via @spakjs/cli. All outputs are colorized and human-friendly. Spak 通过 @spakjs/cli 提供 spak 可执行文件，所有输出均为彩色人类友好格式。 

# Configuration management (persists to ~/.spak/config.json)
spak config get <key>
spak config set <key> <value>
spak config list

# Switch UI language
spak config set language zh   # switch to Chinese
spak config set language en   # switch back to English

# Plugin security checks (CPC) — requires cpc.enabled: true
spak cpc check
spak cpc status
spak cpc sandbox <plugin-name>
spak cpc circuit <plugin-name>

Configuration配置文件

Create spak.config.yml in your project root. Example from the spak repo itself: 在项目根目录创建 spak.config.yml。下方示例直接来自 spak 仓库本身： 

name: spak-test
plugins:
  '@spakjs/plugin-server':
    host: 0.0.0.0
    port: 4321
  '@spakjs/plugin-http': null
  '@spakjs/plugin-daemon':
    enabled: true
    logFile: spak.log

The loader supports variable interpolation (${{ env.XXX }}, ${{ pkg.version }}) and $if conditional loading (booleans, literals, interpolated truthiness all work). loader 支持变量插值（${{ env.XXX }}、${{ pkg.version }}）与 $if 条件加载（boolean、字面量、插值后的真假均可正确判断）。

Architecture架构

core is the engine, spak is the assembled car. You can use @spakjs/core alone, or import { createApp } from 'spak' for the whole thing. core 是引擎，spak 是把引擎装配好交付的整车。你可以单独用 @spakjs/core，也可以直接 import { createApp } from 'spak' 一行起步。 

                       spak (Facade / 整车入口)
                              │ re-exports
  ┌────────────┬──────────────┼──────────────┬──────────────┐
  │            │              │              │              │
 CLI        Plugins        Loader         Config         I18n
spak-cli   daemon/hmr/     NodeJS         ~/.spak/      LocaleTree
           server/http     yml+fork       JSON store    + T()
  │            │              │              │              │
  └────────────┴──────────────┴──────────────┴──────────────┘
                              │
                         @spakjs/core
                  Context / Commander / Middleware
                  Permissions / Schema / I18n render
                  Session / Filter
                              │
              ┌───────────────┴───────────────┐
        @spakjs/util                      @spakjs/message
        纯函数（零副作用）                  h()/Fragment（零副作用）
                              │
                         @spakjs/log
                  多 transport logger（Node 层）

Layering rule: dependency direction is always top-right → bottom-left. No @spakjs/* package may import 'spak'. 分层铁律：依赖方向永远「右上 → 左下」，任何 @spakjs/* 包都不得 import 'spak'。

Entry points: 入口选择：

  • import { createApp } from 'spak' — full car完整整车
  • import { Context } from '@spakjs/core' — kernel only只要内核跑命令系统
  • import { h } from '@spakjs/message' — 8KB, no cordis dep8KB，无 cordis 依赖
  • import { createLogger } from '@spakjs/log' — zero third-party deps零第三方依赖

Logging — @spakjs/log日志 — @spakjs/log

A multi-transport structured logger. Zero third-party deps, Node environment (file transport needs fs). Does NOT depend on @spakjs/core — any project can use it independently. 多 transport 的结构化日志包。零第三方依赖，Node 环境（file transport 需要 fs）。不依赖 @spakjs/core，可被任何项目独立使用。 

import { createLogger, configureLogger, FileTransport, ConsoleTransport, LogLevel } from '@spakjs/log'

configureLogger({
  level: LogLevel.debug,
  transports: [
    new ConsoleTransport(),
    new FileTransport({ path: 'app.log', maxSize: 5 * 1024 * 1024 }),
  ],
})

const log = createLogger('my-scope')
log.info('服务启动', { port: 3000 })
log.warn('内存偏高', { rss: '420MB' })
log.error('请求失败', new Error('timeout'))

Log levels: silent(0), error(1), warn(2), info(3), debug(4), trace(5). Global level + per-transport level filter together. 日志级别：silent(0)、error(1)、warn(2)、info(3)、debug(4)、trace(5)。全局 level 与各 transport 独立 level 共同过滤。

Transports: ConsoleTransport (colored, stderr for warn/error), FileTransport (append + auto-rotate by maxSize, silent on write failure), StreamTransport (any write(str) target). Transport：ConsoleTransport（染色，warn/error 走 stderr）、FileTransport（追加写 + 按 maxSize 时间戳重命名轮转，写入失败静默吞掉）、StreamTransport（任意带 write(str) 的对象）。

Bridge cordis Logger via attachCordis({ Logger: CordisLogger }) — best-effort, safely no-ops if cordis contract changes. 通过 attachCordis({ Logger: CordisLogger }) 桥接 cordis Logger——best-effort，cordis 契约变更时安全 no-op。

Security — CPC安全 — CPC

CPC (Check Plug-in Collection) is the only module responsible for plugin security. Located in packages/spak-cli/src/commands/cpc.ts, invoked via spak cpc <subcommand>, requires cpc.enabled: true in spak.config.yml. CPC（Check Plug-in Collection）是仓库内唯一负责插件安全措施的模块，位于 packages/spak-cli/src/commands/cpc.ts，通过 spak cpc <subcommand> 调用，需在 spak.config.yml 里 cpc.enabled: true 才可用。

Capabilities (honestly documented status): 能力清单（如实标注的状态）：

  • Plugin Check — ✓ usable可用 — validates package structure, main entry, deps integrity校验包结构、main 入口、依赖完整性
  • Sandbox — ⚠ partial部分 — detached child process shell, but target plugin not actually loaded yetdetached 子进程壳已就位，但尚未真正加载运行目标插件代码
  • SSetPS — ✓ usable可用 — samples RSS every 10s, warns at 80% of 512MB, tries global.gc()每 10s 采样 RSS，超 512MB 上限的 80% 告警，并尝试 global.gc()
  • Circuit Breaker — ⚠ partial部分 — state map exists, no runtime path consumes it yet熔断状态表已维护，但目前无运行时路径读取该表拦截插件
  • Firewall — ⚠ stub占位 — console.log only, no real allow/deny仅 console.log，无真实 allow/deny 拦截

This honest "what's done vs stubbed" table is lifted verbatim from docs/security.md. We don't pretend partial features are production-ready. 这张"已完成 vs 占位"对照表逐字摘自 docs/security.md。我们不会把部分实现假装成生产可用。
